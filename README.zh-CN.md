# i-am-lazy

[English](README.md) | [日本語](README.ja.md) | 简体中文 | [한국어](README.ko.md)

AI 问你"可以检查一下吗？可以的话请回复'执行'"，你只好回一句"执行"。
它说"请试一下再告诉我结果"，最后还是你自己去确认。
上周说过的事，又得从头解释一遍。

i-am-lazy 就是为了消灭这些来回。AI 智能体会自己查、自己做、自己验证结果，然后再向你汇报。你最多只需要在最后输入一个 `y`。

## 使用前后对比

`生产环境挂了吗？`

> **使用前：** 我这边无法查看生产环境的状态。如果可以通过 SSH 检查，请回复"执行"。
>
> **使用后：** 没挂。已在生产环境执行 `docker ps`：3 个容器都已运行 2 天，最近 1 小时的日志没有错误。

`看一下这个`（附上代码差异）

> **使用前：** 发现 3 个问题，已经修复并提交了。
>
> **使用后：** 发现 3 个问题：1. 没有检查令牌有效期 2. 出错时返回成功 3. 没有测试。要修复吗？输入 `y` 会修复全部 3 个并运行测试。

## 带来的变化

- **不再等待许可：** 查看日志或生产环境状态这类只读操作，直接执行。
- **不做你没要求的事：** "看一下"只汇报，"修复"会修复并验证，"提交"只提交不推送。
- **不再以"请试一下"结尾：** 测试和生产环境的确认都由它自己完成，并把结果给你看。
- **简短指令就够了：** `push`、`1`、`都要` 就能执行。语音输入里的口头禅和停顿也能理解。
- **说一次就够：** 你指出的问题会记录到指令文件里，不用重复。
- **问题好回答：** 必要的问题一次问完，用 `1` 或 `y` 就能回答。

## 为什么可以放心交给它

省掉的是麻烦，决定权仍然在你手里。以下操作一定会先等你输入 `y`：

- 删除数据等无法撤销的操作
- 会产生费用的操作
- 发布、发送等他人可见的操作
- 修改生产环境

它不会输入密码、API 密钥或支付信息。

## 安装

Claude Code 只需一行：

```bash
git clone https://github.com/spa77k/i-am-lazy.git && mkdir -p ~/.claude/skills && cp -r i-am-lazy/skills/i-am-lazy ~/.claude/skills/
```

安装后照常对话即可。"懒得弄""你直接做吧"这类简短指令会自动触发，也可以用 `/i-am-lazy` 主动调用。
