# i-am-lazy

[English](README.md) | 日本語

ユーザーの手間を最小限にするための、AIエージェント向けスキルです。AIが自分で調べ、作業し、結果を確かめます。ユーザーに残す作業は、最後に1つまでにします。

## 防ぐ対応

| よくある指摘 | AIの対応 | i-am-lazy での対応 |
|---|---|---|
| `やれ` | 「確認してよければ『やって』と言ってください」と許可を求めた | 読み取りだけの作業は、許可を求めずに行う |
| `見ろよ、本番を` | 手元のコードだけを見て回答した | 本番環境、実際のファイル、画像を先に確認する |
| `確認した？` | 「試して教えてください」で返答を終えた | テストと本番の確認を自分で行い、結果を示す |
| `見てと言っただけ` | 依頼されていない修正まで行った | 依頼の動詞で作業範囲を決める（「見て」は報告のみ） |
| `違う、〇〇って意味` | 短い指示や音声入力を読み違えた | `1,5`、`両方`、言いよどみを含む音声入力を正しく解釈する |
| `ハーネス強化しろ` | 指摘を記録しなかった | 指摘をその場で指示ファイルに書き足す |
| `うざい` | 毎回「推測です」と断りを入れた | 前提の断りは1回だけにする |

## 適用前と適用後

ユーザーの入力：`本番落ちてない？`

適用前：

> 本番の状態はこちらからは分かりません。SSHで確認してよければ「やって」と言ってください。

適用後：

> 落ちていません。本番で `docker ps` を確認しました。3つのコンテナはすべて2日間稼働しており、直近1時間のログにエラーはありません。

## 8つの規則

1. 読み取りは自由に行い、書き込みは依頼の動詞の範囲で止める
2. 回答する前に、実際の環境や成果物を確認する
3. 自分で実行できる手順を、ユーザーに渡さない
4. 動作の確認は自分で行う
5. 短い指示と音声入力を正しく解釈する
6. 指摘はその場で記録し、同じ指摘を二度受けない
7. 迷ったら妥当な既定値で決める。質問するときは `1` や `y` で答えられる形にする
8. 断りは1回だけにする

## 安全のための制限

次の操作は、このスキルを使っていても自動では行いません。必ずユーザーの承認（`y` の1文字）を得てから実行します。

- データの削除など、取り消せない操作
- 支払いが発生する操作
- 公開や送信など、他の人に見える操作
- 本番環境の変更
- パスワード、APIキー、支払い情報の入力（これらはユーザー自身が行います）
