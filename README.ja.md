# i-am-lazy

[English](README.md) | 日本語 | [简体中文](README.zh-CN.md) | [한국어](README.ko.md)

AIに「確認してよければ言ってください」と聞かれて、「やって」と返す。
「試してみてください」と言われて、結局自分で確かめる。
前にも伝えたことを、また最初から説明する。

i-am-lazy は、こうしたやり取りをなくすスキルです。AIエージェントが自分で調べ、作業し、結果を確かめてから報告します。あなたがすることは、多くても最後に `y` を打つくらいです。

## 使う前と使った後

`本番落ちてない？`

> **使う前**：本番の状態はこちらからは分かりません。SSHで確認してよければ「やって」と言ってください。
>
> **使った後**：落ちていません。本番で `docker ps` を確認しました。3つのコンテナはすべて2日間稼働しており、直近1時間のログにエラーはありません。

`これ見て`（変更差分を渡して）

> **使う前**：問題が3つあったので、直してコミットしました。
>
> **使った後**：問題が3つあります。1. トークンの期限を確認していない 2. エラー時に成功を返している 3. テストがない。直しますか？ `y` で3つとも直し、テストまで実行します。

## 変わること

- **許可待ちがなくなる**：ログや本番の状態を見るだけなら、聞かずに確認します。
- **頼んだ以上のことはしない**：「見て」なら報告だけ。「直して」なら修正と確認まで。「コミットして」ならpushはしません。
- **「試してください」で終わらない**：テストも本番の確認も自分で行い、結果を見せます。
- **短い指示で伝わる**：`push`、`1`、`両方` だけで動きます。音声入力の言いよどみも読み取ります。
- **同じことを二度言わなくていい**：一度指摘したことは、指示ファイルに記録されます。
- **質問は答えやすく**：必要な質問は1回にまとめ、`1` や `y` で答えられる形で聞きます。

## 任せても大丈夫な理由

手間は減らしても、判断はあなたに残します。次の操作は、必ずあなたの `y` を待ってから行います。

- データの削除など、取り消せない操作
- 支払いが発生する操作
- 公開や送信など、他の人に見える操作
- 本番環境の変更

パスワード、APIキー、支払い情報の入力は行いません。

## インストール

Claude Code の場合、次の1行で入ります。

```bash
git clone https://github.com/spa77k/i-am-lazy.git && mkdir -p ~/.claude/skills && cp -r i-am-lazy/skills/i-am-lazy ~/.claude/skills/
```

入れたあとは、いつも通り話しかけるだけです。「やっといて」「だるい」のような短い指示で自動的に使われます。`/i-am-lazy` で明示的に呼ぶこともできます。
